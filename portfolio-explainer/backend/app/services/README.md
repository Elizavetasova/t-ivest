services/ нужен, чтобы отделить API от бизнес-логики.

Например:

- routes/portfolio.py принимает запрос;

- portfolio_service.py получает mock-портфель и рассчитывает показатели;

- schemas/portfolio.py проверяет структуру ответа.

Важный момент: контракт и код — не одно и то же
Допустим, вы записали в api-contract.md:
GET /api/v1/portfolio/{portfolio_id}

Это пока только описание.

Чтобы endpoint действительно работал, нужно реализовать его в routes/portfolio.py и подключить в main.py.

FastAPI не читает api-contract.md и не создаёт endpoint-ы автоматически.

Реализация одного endpoint целиком, чтобы понять весь путь данных:

Начать с:
GET /api/v1/portfolio/demo-001

1. Mock-портфель.
2. Pydantic-модель.
3. FastAPI endpoint.
4. Проверка через /docs.
5. Вызов endpoint-а из React.
Когда это заработает, аналогичным образом будет проще реализовать POST для AI-объяснения.

Так вы получите первый работающий вертикальный срез продукта, а не просто набор пустых файлов.
